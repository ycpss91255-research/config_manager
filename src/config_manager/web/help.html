納管一份設定檔

把一份已經在這台機器上的設定檔交給系統管理。納管不會改動檔案內容，只是從這一刻起開始追蹤它。

  1. 按標題列的 納管。
  2. 從列出的目錄一路點進去，找到那個檔案。只有白名單裡的目錄看得到。也可以在上方的路徑欄貼上目錄或檔案的完整路徑，按 前往；貼的是檔案，就會跳到它所在的目錄並選好它。
  3. 選好檔案後按 檢視並納管。
  4. 確認畫面會列出偵測到的格式與內容摘要。有幾種讀法的值（例如 yes、08）會請你逐一勾選確認。
  5. 按 確認寫入。這份設定檔會出現在左側清單，狀態是 一致。

要納管的目錄不在白名單裡時，一般使用者請開發者把它加進去；開發者可以在被拒絕的畫面上直接加，或按標題列的 白名單。

修改參數並進版

改值分兩步：先儲存成草稿，再進版。進版之前，機器上的檔案不會變。

  1. 在左側清單雙擊那份設定檔（或選取後按 Enter），右側會出現參數欄位表。
  2. 改你要改的值。來源值 那一欄是目前已進版的值，方便對照。格式不對的欄位會當場標出來並說明怎麼修。
  3. 按 儲存。這時改動是草稿：沒有紀錄，也還沒寫到機器上。
  4. 要改的都存好之後，按標題列的 進版（按鈕上的數字是待進版的草稿份數）。
  5. 確認之後，所有草稿一次驗證、留下變更紀錄、寫到各自的目標位置。

不想要這些草稿了，按 捨棄變更。它只丟掉草稿，已進版的內容與機器上的檔案都不動。

進版是全域動作：一次把所有設定檔的草稿一起進版，不是只進目前看的那一份。

退版

把一份設定檔回復到先前的某個版本。退版是「再記一筆新的變更」，不會把歷史抹掉。

  1. 展開那份設定檔，按 歷史。
  2. 點一筆紀錄，右邊會列出那一次改了什麼（哪個參數從什麼改成什麼）。每一筆都有作者與時間。
  3. 找到要回去的那一筆，下面那一行會寫退回會改變幾個參數。按 退回此版本，確認框會逐項列出「目前 → 退回後」，確認。

退回是讓內容回到那一筆完成之後的樣子，不是撤銷那一筆。想回到某一次修改之前，要選它前面那一筆（第一次修改之前就是「納入管理」那一筆，在「全部」裡）。

退版之後內容會寫回目標位置，歷史裡多一筆「退回舊版本」的紀錄。

這份設定檔還有沒進版的草稿時不能退版。先進版，或先捨棄草稿。

處置偏離

偏離 的意思是：機器上的檔案和系統記得的不一樣，有人沒透過這個介面直接改了檔案。系統不會自己處置，要由人決定。

  1. 按 檢查差異，清單會標出哪幾份偏離。
  2. 展開偏離的那一份，按 檢視差異，看兩邊差在哪裡。
  3. 三選一：
    • 以來源覆蓋目標：現場的修改不要了，用系統記得的內容蓋回去。會先請你確認，並留下紀錄。
    • 將目標現況納入來源：現場的修改是對的，把它收進系統。內容要通過驗證才收得進來。
    • 先納入、待修正：現場的內容有不合規定的值，但想先收進來再慢慢修。它會變成一份草稿，修好之後再進版。

目標檔不見了：寫出到目標

未部署 的意思是：系統裡有這份設定檔的內容，但機器上那個位置沒有檔案（被刪掉或搬走了）。

  1. 按 檢查差異，找到狀態是 未部署 的那一份。
  2. 展開它，畫面會說明缺的是哪個位置的檔案。
  3. 按 寫出到目標。系統把記得的內容寫回去，擁有者與權限也照紀錄設好，狀態回到 一致。

這條路只補不存在的檔案，不會覆蓋既有的內容。那個位置已經有檔案的話，它會拒絕、檔案原封不動。要用系統記得的內容蓋過一個還在的檔案，走「處置偏離」的 以來源覆蓋目標——那條路會先確認，並留下是誰、何時蓋掉的紀錄。

寫出到目標不會改動系統記得的內容，所以它不會留下變更紀錄。

角色與模式

角色決定你能做什麼，模式決定這套服務怎麼運作。兩者互不影響。

角色：輸入身分時自己選

角色能做的事
一般使用者納管、修改參數、進版、退版、處置偏離、解除納管。
開發者以上全部，另外可以：改設定檔的屬性（名稱、群組、主機、說明）、指定參數的型別、產生 schema、維護白名單。

畫面上標著「🔧 開發者」的入口，是只有開發者才有的操作。一般使用者的畫面上不會出現這些入口——看不到某個按鈕不是壞掉，也不是權限被關掉，是那個操作屬於另一個角色。需要的話，退出後重新選角色。

這裡沒有密碼，角色是自己選的。它的用途是讓不常用的操作不要擋在日常畫面上，不是用來管制誰能做什麼。

模式：由服務決定，畫面右上角看得到

模式差別
部署模式一段時間沒有操作會自動退出（逾時前會提示，按 繼續使用 可以延長）。沒有「記住此裝置」。現場用的是這一種。
開發模式不會因為閒置被退出；身分輸入頁可以勾 記住此裝置，下次不必再填姓名與 Email。

常見問題

為什麼我的畫面是唯讀，不能改？

同一時間只有一個人能編輯。別人正在編輯的時候，你的畫面上方會出現橫幅，寫著是誰、從什麼時候開始，而所有會寫入的按鈕都不出現。等對方進版、捨棄或關掉頁面之後，重新整理就能取得編輯權。對方的頁面當掉沒有正常關閉的話，過一陣子系統會自動收回。沒有「強制接管」。

為什麼又要我重新輸入身分？

身分記在你這個瀏覽器上，而且這不是登入——沒有帳號可以「保持登入」。下面幾種情況都要重新輸入：關掉瀏覽器再開、換一個瀏覽器或另一台電腦、部署模式下閒置太久被自動退出、服務重新啟動過。開發模式下可以勾 記住此裝置 省掉姓名與 Email，角色仍然每次要選。

我按了儲存，為什麼機器上的檔案沒變？（草稿還沒進版）

儲存 只是把改動存成草稿。草稿不留紀錄，也不寫到機器上。要讓改動生效，按標題列的 進版。按鈕上的數字不是 0，就代表還有草稿沒進版。

清單上寫「錯誤」是什麼意思？

系統讀不到要比對的檔案，所以判不出它的狀態。那一列底下寫著原因（例如 Permission denied）與下一步，照著處理（例如補上讀取權限）之後，按 檢查差異 重新比對。展開那一份，區塊裡也會說明讀不到的原因。

服務重啟之後，我的草稿去哪了？

沒有了。草稿只留在服務的記憶體裡，服務一重啟就消失，救不回來。已經進版的內容、歷史、清單與白名單都還在。改到一半要離開很久、或知道服務要重啟之前，先進版。

備份與還原

這一段是給管理這台機器的人看的：指令要在機器上執行，不在這個頁面上。完整步驟在隨程式附的部署文件（doc/DEPLOYMENT.md 的「備份與還原」）。

這不是整機備份。備份的只有系統記得的東西：納管清單、每一份設定檔已進版的內容、白名單、全部的變更歷史。機器上實際的設定檔不在備份裡，還沒進版的草稿也不在。

備份

服務不必停，隨時可以做：

just docker backup /path/to/backups

做出來的是一個檔案。指令說完成的時候，那個檔案已經被實際還原過一次確認可用。把它放到另一台機器或另一顆磁碟上。

還原

還原之前有兩個條件，少一個指令就拒絕、什麼都不動：

  1. 服務已經停了。
  2. 系統的資料是空的。還原不會覆蓋、也不會替你清掉現有的資料。
just docker restore /path/to/backups/config-repo-….bundle

還原之後

還原回來的是系統記得的內容，機器上的檔案沒有被動過。啟動服務後按 檢查差異，系統會重新比對：

  • 一致：不用做什麼。
  • 未部署：檔案不見了，照「目標檔不見了」那一段用 寫出到目標 補回來。
  • 偏離：檔案在備份之後被改過。系統不會自動覆蓋，照「處置偏離」那一段決定。

名詞對照

名詞意思
納管把一份已經在機器上的設定檔交給系統管理。過程不改檔案內容。
解除納管停止管理。機器上的檔案留著，系統不再追蹤它。
來源系統記得的那一份內容。系統認定它是正確的版本。
目標位置設定檔在機器上實際被程式讀取的路徑。
草稿已經在介面上改了、但還沒進版的內容。不在來源裡，也不在機器上。
進版把全部草稿一次驗證、留下紀錄、寫到機器上。
退版回復到先前的版本。以一筆新的變更完成，不改寫歷史。
寫出把來源的內容寫到目標位置，並設好擁有者與權限。
納入把機器上檔案的現況收回來源。
白名單系統可以碰機器上哪些目錄的清單。不在裡面的目錄看不到、也納管不了。
一致機器上的檔案與來源相同。
偏離機器上的檔案與來源不同，代表有人繞過介面直接改了。唯一的異常狀態。
未部署機器上那個位置沒有檔案。
錯誤系統讀不到要比對的檔案（多半是機器上的目標，也可能是系統記得的來源），所以判不出是一致、偏離還是未部署。這不是另一種狀態；原因與下一步直接寫在那一列底下。

這不是登入：輸入的姓名與 Email 只用來讓每一筆變更追溯得到人，沒有密碼，也不會驗證。
