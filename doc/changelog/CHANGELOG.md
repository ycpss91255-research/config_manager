# 變更紀錄

**粒度是版本里程碑，不是逐次變更。** 一個版本一筆，記這一版對使用者的意義，在
milestone 關閉時寫。版本依設計文件 §8 的里程碑階梯。

逐次變更的細節不在這裡，各有去處：**為什麼長成這樣** → `doc/adr/`；**一次變更做了
什麼與為什麼** → commit 內文（本 repo 的 commit 內文非常詳細）；**目前能做什麼** →
README 的「目前狀態」；**還缺什麼** → GitHub milestone 與 issue。這個粒度的決定與
理由記在 ADR-00000030（服務不變式 9）——先前以「能力／逐次變更」為粒度時，維持它
一致的唯一機制是人的記憶，而漏掉不發出訊號，2026-09-05 的補寫就落後了 37 個 commit
（`#142`）。

紀錄一律以中文書寫（ADR-00000028：專案文件）。

### v0.1.0 — 資料層與唯讀介面

config repo 成為唯一真實來源的骨幹落地。檔案以原子方式寫出（要嘛完整、要嘛不動），
變更由 git 記錄且退得回，服務起來前先驗證清單與來源，偏離以內容雜湊偵測。服務起得
來，唯讀 HTTP 回得了 config 清單，瀏覽器看得到每一筆的部署狀態（一致／偏離／未部署），
而 CLI 與網頁看到的是同一份。輸入身分成為變更紀錄的作者。

**這一版是唯讀的。** 寫入路徑——進版、退版、偏離處置、編輯階段——隨後續里程碑到
（設計 §8 的階梯）。
