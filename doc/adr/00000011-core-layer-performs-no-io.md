# The core layer performs no I/O and every module is independently callable

> 服務：不變式 7（經設計原則 N-4）

- **Date:** 2026-09-02
- **Status:** Accepted

## Context

狀態判定與驗證是整個系統的地基，其正確性必須有快速可靠的測試。
若這些邏輯直接讀檔或呼叫 git，測試就需要準備真實環境，慢且脆。

## Decision

依賴方向 `api → core → io` 單向。核心層不碰檔案系統與 git。

每個模組的輸入與輸出都必須明確到可以單獨呼叫、單獨測試：輸入全部來自參數
（不從環境變數、不從全域狀態）；輸出為回傳值或具名例外（不以修改傳入物件
作為主要輸出）；模組間無隱含呼叫順序。

## Alternatives

- **分層但允許核心層讀檔**：測試仍需準備檔案系統，等於沒有分層。
- **以 mock 取代**：mock 檔案系統的行為細節（權限、原子性、錯誤碼）
  比把 I/O 隔離出去更難維護。

## Consequences

- 可驗證的判準：核心層的每支測試都能在沒有檔案系統、沒有 git、沒有網路的
  情況下跑完。做不到就代表該模組有隱藏依賴，是設計問題不是測試問題。
