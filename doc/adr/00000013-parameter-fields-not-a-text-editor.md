# 介面以帶型別的參數欄位編輯，絕不編輯檔案文字

> 服務：不變式 2 ＋ 產品目標

- **Date:** 2026-09-02
- **Status:** Accepted

## Context

介面若提供文字框讓使用者輸入 YAML，與使用 vim 沒有區別：使用者一樣要自己
處理縮排、引號與型別，所有關於型別安全與結構驗證的設計都失去意義。

## Decision

介面呈現一列一個參數的欄位表，每個參數依型別給對應的輸入控制項。
型別由系統決定，一般使用者不可改（開發者可指定，見 ADR-00000021）。

布林 → 核取方塊；整數 → 整數輸入框；浮點 → 允許小數的輸入框（**輸出一定帶小數點**，
直接消除 ROS 2 最常見的型別錯誤）；列舉 → 下拉選單；字串 → 文字框（引號由系統處理）；
陣列 → 可增刪的列**並可調整順序**；巢狀物件 → 可折疊區塊，內部遞迴套用。

**不用拉霸**——拉霸適合即時視覺回饋，config 調參需要的是精確輸入。

## Alternatives

- **線上文字編輯器（如 Monaco）**：等同 vim，放棄型別保護。
- **Tweakpane / lil-gui**：視覺語言最接近，但**沒有陣列綁定**（支援型別僅數值、
  字串、布林、色彩、二至四維點），且**沒有每欄位的驗證錯誤呈現**；其核心賣點
  拉霸與即時監看正是本專案不需要的。
- **只提供陣列的新增與移除**：要把第三項移到第一位就得刪掉重打，會遺失原值也容易打錯。
  **順序本身就是資料**，必須能直接操作。
- **自建渲染器**：完全符合但需自行維護，作為備案。

## Consequences

- 起步採用由 schema 生成表單的既有函式庫（支援陣列與巢狀、有欄位級驗證呈現、
  無建置流程）。因此**整個 v0.10.0 都不需要打包工具**。
- 型別未知或結構無法表格化的項目退回文字區塊，並**明確標示為未結構化編輯**——
  使用者看得到自己失去了型別保護。
