# Deploy config by copy and apply rather than by symlink

> 服務：不變式 2

- **Date:** 2026-09-02
- **Status:** Accepted

## Context

把檔案搬進 repo、原位置建立符號連結是常見做法（GNU Stow 模式），初看最簡潔。

## Decision

採用複製 + 寫出：repo 為來源，寫出時產生一般檔案至目標位置。

## Alternatives

- **符號連結（Stow 模式）**：三個失效模式——(1) 容器內解析不到 repo 路徑會斷鏈，
  須額外掛載且路徑須一致，此約束會傳染至每個新服務；(2) 寫暫存檔再改名的寫入方式
  會把符號連結替換成一般檔案並**靜默失效**；(3) repo 與目標為同一份檔案，無法區分修改來源。
- **裸 repo 原地追蹤（yadm 模式）**：零侵入，但工作樹指向根目錄使 reset 與分支切換
  語意危險，僅能逐檔操作，不利整批進退版。

## Consequences

- 目標位置的檔案是產物，可被覆蓋——這是刻意的。
- 容器掛載不需任何特殊處理，服務定義維持單純。
- 需要偏離偵測機制，因為 repo 與目標是兩份獨立檔案。
