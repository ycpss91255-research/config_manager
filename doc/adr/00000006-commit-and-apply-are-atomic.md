# 記錄變更與寫出是單一的原子操作

> 服務：不變式 2

- **Date:** 2026-09-02
- **Status:** Accepted

## Context

若記錄與寫出可以分離，系統會存在「已記錄未套用」的中間狀態。
此時「目標 != 來源」就有兩種可能來源，偏離偵測無法判斷是哪一種。

## Decision

記錄與寫出成對發生，任一失敗則整體回滾。不保留中間狀態。
寫出本身採「寫暫存檔 → 落盤 → 設定權限 → 改名」，改名在同一檔案系統內是原子的。

## Alternatives

- **分離的 staged 模式**（先記錄、後審核套用）：需額外記錄上次寫出的內容雜湊
  以區分兩種狀態。若未來需要審核流程再引入。

## Consequences

- 「目標 != 來源」的語意唯一確定為「有人繞過介面修改」，偏離偵測因此可靠。
- 寫出中斷不會產生半殘檔案。

**Amendment (2026-09-02):** 本決策未變，但其適用範圍需要澄清。原子性講的是
**記錄與寫出這一對**，不是「使用者的儲存動作必須立刻記錄並寫出」。

介面設計曾把兩者混為一談，導致一次調整三份 config 會產生三次版本迭代。
ADR-00000022 引入草稿層（編輯 → 儲存為草稿 → 進版），**草稿層在記錄與寫出之前，
不影響本決策的保證**——草稿不在來源 repo 也不在目標位置，因此「目標 != 來源」的
語意仍然唯一確定為「有人繞過介面修改」。

實作時請一併閱讀 ADR-00000022。
