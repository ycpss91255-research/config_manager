# Browser end-to-end tests verify behaviour, selected by semantics

> 服務：不變式 7（維持嚴謹且與業界對齊的測試門檻）

- **Date:** 2026-09-02
- **Status:** Accepted
- **Relates to:** ADR-00000018

## Context

介面工作佔了目標版本的一半（v0.6.0–v0.9.0）。若介面沒有自動化測試，這半段的
缺陷只能靠人工驗收發現——而人工驗收無法在每次提交時執行，也無法防止回歸。

但前端測試有一個常見的失敗形態：對著 DOM 結構斷言（CSS class、元素排列順序、
DOM 路徑）。這類測試在改樣式時就壞，而行為根本沒變——正是 ADR-00000018 所列的
「耦合實作」反模式，只是換到瀏覽器層。

## Decision

新增測試介面 **T11：瀏覽器端到端行為**，以自動化瀏覽器操作真實的前後端。

**測的是使用者看得到的行為**：納管後項目出現在樹上、輸入非法值時儲存按鈕停用、
外部修改後顯示偏離、開第二個分頁時顯示唯讀並指出持有者。

**選取元素以語意屬性為準**——角色、可見標籤文字、`data-testid`——不用 CSS class
或 DOM 路徑。詳見 `doc/UI-ELEMENTS.md`。

**每個版本的驗收檢查點至少對應一條 T11 測試。**

## Alternatives

- **只靠人工驗收**：無法在每次提交執行，無法防止回歸。介面佔目標版本的一半，
  這段完全沒有自動化保護是不可接受的缺口。
- **對 DOM 結構斷言**：改樣式即壞而行為沒變，是耦合實作反模式。
- **元件層級的單元測試**：單一 HTML + 原生 JS 的形態下沒有元件邊界可測。
- **視覺回歸（截圖比對）**：對樣式改動極度敏感，失敗時無法區分「壞了」與「改了」。

## Consequences

- 前端需要為受測元素加上語意屬性。這是刻意的成本，換來測試與樣式解耦。
- T11 走真實容器，執行較慢，屬 system 層級，不在每次存檔時跑。
- 「不測前端 DOM」這條保留，但範圍縮小為 DOM 結構、CSS class 與元素排列順序。
