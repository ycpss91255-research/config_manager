# Development and test tooling. Kept apart from requirements.txt so the
# runtime stage cannot accidentally ship a linter.
#
# requirements.txt is what `devel-base` installs, and `runtime` is FROM
# devel-base -- so anything added there ships in the deployable image.
# Test tooling belongs here and in the `FROM runtime` test stages only (#97).
-r requirements.txt

# 檢查工具一律釘在確切版本（`==`），不寫範圍（ADR-00000027）。
#
# `ruff>=0.5` 的意思是「建映像那一刻最新的那一版」：CI 每次重建工具映像，本機走 layer
# cache，於是同一個 commit 在兩邊由不同版本的工具檢查。ruff 0.17.0 改了一個預設值，CI 就對
# 14 處沒人動過的程式碼報錯，本機照樣全綠（#310、#311）。釘住之後，工具換版是一筆看得見的
# commit，不是某一次無關的 PR 忽然變紅。由 test/bats/unit/dependencies.bats 擋。
#
# 升級檢查工具（想升的時候才升，不會自己發生）：
#   1. 看哪些有新版：
#        docker run --rm config_manager-test-tools:local pip list --outdated
#   2. 改下面那一行的版本號。一次升一支，紅了才知道是誰。
#   3. ./script/test.sh ——這份檔案一變，工具映像的那一層自己重建，裝的就是新版。
#   4. 新版多報的東西在同一個 PR 修掉，commit 用 chore(deps)。
# 這份檔案是唯一寫版本的地方：docker/Dockerfile.test-tools、Dockerfile 的 devel 階段都裝
# 這一份，runtime-test 階段的 pytest 也是從這裡讀那一行，所以本機、CI 的 checks、CI 的 build
# 用的是同一組版本。
pytest==9.1.1
pytest-cov==7.1.0
ruff==0.17.0
mypy==2.4.0
pylint==4.1.3

playwright==1.63.0
