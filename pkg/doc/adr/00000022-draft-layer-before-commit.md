# Saving a draft is separate from committing and applying

> 服務：不變式 2（絕不靜默失敗）

- **Date:** 2026-09-02
- **Status:** Accepted
- **Relates to:** ADR-00000006

## Context

ADR-00000006 規定記錄與寫出是單一原子操作。該規定針對的是「不留下已記錄未套用
的狀態」。

但先前的介面設計把它誤推成：**每個 config 區塊的儲存按鈕 = 立刻記錄 + 立刻寫出**。

後果是：使用者一次調整三份相關的 config，會產生三次獨立的版本迭代——而它們在語意上
是**同一次調整**。歷史被切碎；退版時也無法一次退回那批改動之前的狀態。

## Decision

分成三段：**編輯 → 儲存（草稿）→ 進版（記錄 + 寫出，原子）**

- **儲存**：各區塊的動作，存為草稿。跑第 1 層驗證，不通過則不存。
  **不產生變更紀錄、不寫到目標位置。**
- **進版**：工具列的全域動作，把**全部**草稿一次驗證、記錄、寫出。
- **退版**：與草稿無關，針對單一 config 回到先前版本。

**草稿存在編輯階段的伺服器端狀態中**，不在來源 repo，也不在目標位置。

進版的原子性規則：任一草稿的任一層驗證失敗則**整批不進版**；每份 config 產生一筆
變更紀錄但在同一次操作中完成；寫出過程任一份失敗則整批回滾。

草稿**不是第五種狀態**。四種狀態比較的是目標與來源，草稿與之正交。

## Alternatives

- **維持儲存＝記錄＋寫出**：即本 ADR 要修正的問題。
- **進版時產生單一變更紀錄涵蓋多份 config**：變更紀錄的範圍是 uid（ADR-00000007），
  多份 config 就沒有單一 uid 可放；且「這份 config 改過幾次」會失準。
- **草稿存在瀏覽器端**：重新整理即遺失，且無法在編輯階段逾時時給出明確提示。
- **草稿存在 git 工作區**：會讓來源 repo 的工作區與 HEAD 不一致，偏離偵測就多出
  一種無法分辨的狀態——直接違反 ADR-00000006 想保護的性質。
- **把草稿做成第五種狀態**：「檔案不一致」與「我還沒送出」的處置完全不同。

## Consequences

- 編輯階段需要保存草稿內容，階段狀態不再只有身分與時間戳。
- 階段逾時釋放時草稿一併清除，**必須明確提示**而非靜默丟棄。
- 退出時若有未進版草稿需二次確認。
- 進版按鈕需顯示待進版的草稿數。
- ADR-00000006 的原子性保證不受影響——草稿層在記錄與寫出之前。
