# config-manager — 設計文件包

集中式 config 管理系統的設計文件。**此包只含文件，不含程式碼。**

## 內容

| 檔案 | 放什麼 | 更新時機 |
|---|---|---|
| `doc/PRD.md` | 9 條產品不變式 | 只在產品目標改變時 |
| `doc/adr/` | 22 份決策紀錄 | 只增；可在原檔修訂；推翻才開新號 |
| `doc/TEST-PLAN.md` | 測試項目：18 個測試介面 + 6 個驗收旅程 | **提案，待逐項確認**；新增介面需更新並確認 |
| `doc/UI-ELEMENTS.md` | wireframe ↔ HTML ↔ 測試選取器的對照 | 改介面時三者一起改 |
| `CONTEXT.md` | 領域用語表 | 新增術語時 |
| `tools/` + `figures/` | 圖表產生腳本與輸出 | **改圖就是改腳本再重跑**，不手改 SVG |
| `config-manager-design.pdf` | 設計快照：意圖、理由、形狀的原因 | 隨版本整份更新 |

四者互不重複：**不變式 / 決策 / 詞彙 / 設計快照**。

## 讀的順序

1. **`CONTEXT.md`** — 先統一用語，後面才讀得懂
2. **`doc/PRD.md`** — 9 條不變式，任何設計都不得違反
3. **PDF §0–§8** — 目前的設計長什麼樣
4. **`doc/adr/`** — 為什麼不是別的樣子
5. **`doc/TEST-PLAN.md`** — 動工前先確認測什麼

## 實作方式

**測試先行（red → green）。** 規則見 `doc/TEST-PLAN.md`：

- **沒有經過確認的測試介面，不寫測試。** 動工前先逐項確認該文件。
- 一次一片：一個測試介面、一個測試、一個最小實作。
- 垂直切片，不橫向切片——不先寫完一個版本的所有測試再實作。
- 重構不在 red → green 迴圈裡，它屬於 review 階段。

## 給後續維護者 / agent

- **不要重建這些檔案。** 直接使用；有新決策就在 `doc/adr/` 加新號（從 `00000023` 續接）。
- **ADR 的編號與結構 lint 要在 v0.1.0 就寫**：重號 fail、檔名格式不符 fail、
  缺 `> 服務：` 或必要段落 fail、跳號與缺 Alternatives 僅 warn。
  平行開發撞號是真實發生過的缺陷，人工檢查抓不到。
- **圖表不要手改 SVG。** 改 `tools/` 的腳本再重跑（`cd tools && python3 gen_flows.py`）。
  腳本內建自我檢查，會抓出節點溢出畫布與重疊。
- **Wireframe 是 HTML 的規格。** 實作介面時對照 `doc/UI-ELEMENTS.md`。
- **新增術語前先查 `CONTEXT.md`**，不重新造詞。
- **PDF 中標記為「推導內容」的章節**（目錄樹、端點表、欄位表、閾值表、里程碑）
  在對應程式碼落地後應刪除，改為指向真實來源。見 PDF §0.7。
